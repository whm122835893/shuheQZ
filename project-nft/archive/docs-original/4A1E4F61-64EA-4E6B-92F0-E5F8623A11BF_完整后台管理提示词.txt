
数和文创数字藏品平台 · 运营管理后台（完整开发提示词 V2.1）
一、项目定位
为「数和文创数字藏品平台」构建完整的运营管理后台，面向超级管理员、运营、财务、风控、客服五种角色。PC端为主，同时完整适配 iPhone Safari 等手机浏览器（表格横向滚动、弹窗自适应、支持 PWA 添加到桌面）。
核心原则：所有业务逻辑必须形成闭环，禁止逻辑断层；所有高风险操作必须可审计、可回滚、有边界拦截。
二、技术栈（强制统一，不可变更）
层级	技术选型
框架	Vue 3.3+（Composition API + <script setup> + TypeScript，严格 TS 禁止 any）
构建工具	Vite 4+
UI 库	Element Plus 2.4+
状态管理	Pinia（模块化：admin, permission, app）
路由	Vue Router 4（动态权限路由 + 全局守卫）
HTTP	Axios（统一拦截 JWT，Header: Authorization: Bearer <token>，登录接口除外）
图表	ECharts 5
日期	dayjs（本地化）
富文本	vue-quill-editor 或 tinymce
金额	Decimal.js（字符串传输，展示保留两位小数）
响应规范：后端统一返回 { code, data, message }，code === 200 为成功。
数据规范：布尔字段以 is_ / has_ 开头；时间格式 ISO 8601；分页参数 page（默认1）、page_size（默认20）。

四、全局业务闭环规则（所有模块必须遵守）
4.1 库存体系与配额管理（核心闭环）
4.1.1 库存概念定义（藏品）
•  发行总量：创建藏品时设定，全局唯一基准值，不可变更。例：1000份。
•  已配置配额：所有活动配额（优先购/活动空投/签到/注册/邀请/抽奖等）的总和。配置时从库存池中冻结预留。
•  已售出发售：通过发售渠道（公售/优先购/资格购）实际卖出的数量。
•  已独立空投：通过独立空投实际发放的数量。
•  已销毁：销毁的数量。
•  库存池（自由库存） = 发行总量 - 已配置配额 - 已售出发售 - 已独立空投 - 已销毁。
•  库存池为实时计算值，所有消耗性操作均扣减库存池。
•  发售数量：计划发售数量，配置时 <= 当时的库存池。
•  发售已售：发售中实际卖出的数量。
•  发售剩余：发售数量 - 发售已售（仅展示用，不冻结库存）。
•  流通量：已进入用户仓库的藏品数量 = 已售出发售 + 已独立空投。藏品实际入库到用户仓库后才计入流通量。
•  发行量：即发行总量，固定不变。
4.1.2 库存概念定义（盲盒）
•  盲盒发行总量：创建盲盒时设定，全局唯一基准值，不可变更。例：5000份。
•  盲盒库存池 = 盲盒发行总量 - 盲盒已售出发售 - 盲盒已独立空投 - 盲盒已销毁。
•  盲盒已售出发售：通过盲盒发售渠道实际卖出的盲盒份数。
•  盲盒流通量：已进入用户仓库的盲盒数量 = 盲盒已售出发售 + 盲盒已独立空投。
•  盲盒子藏品（奖品池）：每个盲盒关联 2~N 个子藏品，每个子藏品独立配置中奖概率和计划数量。
•  子藏品计划数量之和不强制等于盲盒发行总量（允许部分盲盒开出空奖或重复奖品）。
•  子藏品实际库存从对应藏品的「库存池」或「配额预留」中冻结。
•  盲盒开启消耗：用户开启 1 个盲盒，盲盒流通量 -1，对应子藏品按概率发放到用户仓库。
4.1.3 配额配置规则（全部可选，任何时间可配置）
可选配额类型（全部可选，可不配、单配、多配，不配的不计入）：
•  优先购配额
•  活动空投配额（签到/注册/邀请/抽奖等活动绑定）
•  其他活动配额
•  配额可在任何时间配置：发售前、发售中、售罄后均可。
•  配置配额时：从库存池中冻结对应数量，变为配额预留库存。
•  约束：新增配额 <= 当前库存池。超发直接拦截并提示「库存池不足，当前库存池为 X」。
•  配额修改：
•  已使用的配额不可减少（防止超卖）。
•  未使用的配额可减少或停用（释放回库存池）。
•  售罄后配额：售罄后库存池 = 发售剩余 + 其他未使用部分，可用这部分配置配额。
4.1.4 发售规则（藏品）
•  发售数量配置时 <= 当时的库存池。
•  发售中实时售卖，每卖出1份：已售出发售 +1，库存池 -1。
•  实际可卖数量 = min(发售数量 - 发售已售, 库存池)。
•  当库存池 = 0 或发售时间到期时，发售自动停止：
•  库存池 = 0 -> 状态自动变为「已售罄」
•  时间到期 -> 状态自动变为「已下架」
•  强制售罄：手动将状态设为「已售罄」，发售停止。未售出的发售剩余保留在库存池中，不清零、不删除。
•  重新上架：「已售罄」或「已下架」状态，可重新配置发售参数（发售数量 <= 库存池）后状态变回「发售中」。
4.1.5 发售规则（盲盒）
•  盲盒发售数量配置时 <= 当时的盲盒库存池。
•  盲盒发售中实时售卖，每卖出1份：盲盒已售出发售 +1，盲盒库存池 -1。
•  实际可卖数量 = min(盲盒发售数量 - 盲盒发售已售, 盲盒库存池)。
•  当盲盒库存池 = 0 或发售时间到期时，发售自动停止：
•  盲盒库存池 = 0 -> 状态自动变为「已售罄」
•  时间到期 -> 状态自动变为「已下架」
•  强制售罄：手动将状态设为「已售罄」，发售停止。未售出的盲盒发售剩余保留在盲盒库存池中。
•  重新上架：「已售罄」或「已下架」状态，可重新配置发售参数（发售数量 <= 盲盒库存池）后状态变回「发售中」。
4.1.6 独立空投规则（藏品）
•  定位：不绑定任何营销活动，纯粹的藏品发放功能。从库存池扣减。
•  独立空投可在任何阶段执行：未发售前、发售中、售罄后，只要库存池 > 0 即可。
•  操作流程：
1.  选择已创建的藏品（自动显示该藏品「库存池」）。
2.  输入空投数量（<= 库存池，实时校验）。
3.  输入接收手机号（批量，换行分隔，每行一个手机号）。
4.  系统校验：手机号格式、是否为平台已注册用户（未注册直接拦截提示）。
5.  二次确认弹窗：展示「藏品名称、空投数量、接收用户数、预计扣减库存池」。
6.  输入管理员密码验证。
7.  提交后：库存池扣减、已独立空投增加、发放藏品到用户仓库、生成发放记录、刷新列表。
•  发放记录：任务ID、藏品名称、空投数量、接收用户数、成功/失败数、操作人、操作时间。支持导出。
4.1.7 独立空投规则（盲盒）
•  定位：不绑定活动，纯粹的盲盒发放功能。从盲盒库存池扣减。
•  操作流程：
8.  选择已创建的盲盒（自动显示该盲盒「盲盒库存池」）。
9.  输入空投数量（<= 盲盒库存池，实时校验）。
10.  输入接收手机号（批量，换行分隔）。
11.  系统校验：手机号格式、是否为平台已注册用户（未注册拦截）。
12.  二次确认弹窗：展示「盲盒名称、空投数量、接收用户数、预计扣减盲盒库存池」。
13.  输入管理员密码验证。
14.  提交后：盲盒库存池扣减、盲盒已独立空投增加、发放盲盒到用户仓库、生成发放记录。
4.1.8 销毁规则
•  藏品销毁：可选择具体数量进行销毁。销毁数量 <= 藏品库存池（不可销毁已配置的配额预留库存）。销毁后：库存池扣减、已销毁增加，不可逆。需二次确认 + 密码验证。
•  盲盒销毁：可选择具体数量进行销毁。销毁数量 <= 盲盒库存池。销毁后：盲盒库存池扣减、盲盒已销毁增加，不可逆。需二次确认 + 密码验证。
4.1.9 强制回收、撤销转赠、撤销空投
•  藏品：成功后藏品从用户仓库移除，归还到库存池（库存池 +1），流通量 -1。
•  盲盒：成功后盲盒从用户仓库移除，归还到盲盒库存池（盲盒库存池 +1），盲盒流通量 -1。
•  前端刷新后数据同步。
4.1.10 活动奖励库存校验
•  全平台所有活动奖励配置藏品时，配置数量为「计划上限」。
•  实际发放时动态校验：该藏品配额预留库存是否充足。
•  先到先得，配额预留不足时拦截提示「配额预留不足，当前剩余 X 份」。
4.1.11 发行量与流通量展示
•  藏品：发行量（发行总量，固定不变）、流通量（实时计算，= 已售出发售 + 已独立空投）。
•  盲盒：盲盒发行量（盲盒发行总量，固定不变）、盲盒流通量（实时计算，= 盲盒已售出发售 + 盲盒已独立空投）。
•  藏品列表/详情页必须同时展示「发行量」和「流通量」。
•  盲盒列表/详情页必须同时展示「盲盒发行量」和「盲盒流通量」。
•  流通量 >= 0 且 <= 发行量。
4.2 资格购（核心闭环）
•  定位：发售藏品的「购买条件限制」，不占独立配额，不冻结库存。
•  配置时机：藏品发售配置时，可选择是否开启资格购（Switch开关）。
•  开启后需配置：
•  资格藏品：选择1个或多个已流通藏品。资格藏品必须是「已有用户持有」的藏品，包括：已发售过的藏品、合成产出的藏品、抽奖获得的藏品、二级市场上流通的藏品。系统仅展示流通量 > 0 的藏品供选择。
•  额外资格手机号：大文本框，换行分隔，每行一个手机号。必须是平台已注册用户，系统校验，未注册直接拦截提示。这些用户无需持有资格藏品即可获得购买资格。
•  购买条件判定流程（用户购买发售藏品时，后端校验）：
Step 1: 用户是否持有该藏品的优先购资格？
|- 是 -> 可直接购买（优先购权限覆盖资格购限制）
|- 否 -> 进入Step 2
Step 2: 该藏品是否开启了资格购？
|- 否 -> 正常购买（无资格限制）
|- 是 -> 进入Step 3
Step 3: 资格购条件判定（满足其一即可购买）
|- 条件A: 用户持有指定的「资格藏品」（1个或多个中的至少1个）
|- 条件B: 用户在「额外资格手机号白名单」中
|- 均不满足 -> 不可购买，提示「未获得购买资格」
•  关键规则：
1.  优先购不参与资格购：持有优先购资格的用户可直接购买，不受资格购条件限制。
2.  只有资格购白名单手机号才能额外参与：不持有资格藏品的用户，只有在额外手机号白名单中才能购买。
3.  资格购只是购买门槛：满足资格购条件的用户，购买时仍受发售「每人限购」约束。
4.  资格藏品必须是流通藏品：只有流通量 > 0 的藏品才能作为资格藏品。
4.3 寄售开关联动（核心闭环）
•  每个藏品拥有独立寄售开关，与全局市场开关、转赠开关完全隔离。
•  开启：持有该藏品的用户可在二级市场挂单寄售。
•  关闭：平台所有该藏品的在售挂单自动全部下架（状态变更为「已下架」），用户无法重新上架该藏品。
•  关闭操作需二次确认 + 管理员密码验证，并记录审计日志。
4.3.1 藏品二级市场开关与价格管控（全局顶层配置）
•  针对单个已发售完毕（或特定状态）的藏品，独立控制是否允许二级市场流通。
•  入口：藏品列表操作列或市场管理独立Tab。
•  操作：
•  开启/关闭二级市场（Switch 按钮）。仅当藏品状态为「已售罄」或「发售中」时可操作。关闭后，该藏品所有在售挂单自动强制下架（状态变更为「系统下架」），用户端不可见且无法新挂单。
•  价格管控模式：开启后必须选择：
•  限价模式（固定金额）：直接输入价格上限和价格下限（单位元，精确到分）。用户挂单价格必须落在此闭区间内（下限 ≤ 价格 ≤ 上限），否则前端拦截提示。
•  不限价模式：用户自由定价（仅保留全局最大金额校验）。
•  列表展示：在监控列表中新增「限价状态」列（限价/不限价）。
•  审计日志：所有开关、限价修改写入 nft_operation_logs。
4.4 转赠开关独立（核心闭环）
•  每个藏品拥有独立转赠开关，与寄售开关互不干扰。
•  关闭：用户端该藏品「转赠」按钮隐藏/置灰，但已发起待确认的转赠不受影响。
•  转赠开关变更无需处理已有转赠记录。
4.5 撤销/回收边界校验（核心闭环）
•  强制回收藏品：操作前校验该藏品是否已被用户二次流转（再次转赠、寄售上架、合成消耗、盲盒消耗）。若已流转，直接拦截并提示「该藏品已发生二次流转，无法回收」。
•  强制回收盲盒：操作前校验该盲盒是否已被用户开启。若已开启，直接拦截并提示「该盲盒已被开启，无法回收」。
•  撤销转赠：仅「已完成」转赠可撤销。操作前校验接收方当前是否仍持有该藏品/盲盒。若已再次转赠/寄售/合成/消耗/开启，直接拦截并提示「接收方已对该藏品/盲盒进行其他操作，无法撤销」。
•  撤销空投：同上述逻辑，校验接收方当前持有状态。
•  所有拦截必须明确提示原因，不可静默失败。
4.6 优先购资格全链路（核心闭环）
•  优先购白名单资格必须设置有效期（精确到时分秒），过期后自动失效。
•  支持批量清理过期资格，清理前需二次确认。
•  用户购买优先购藏品时，校验资格是否有效、剩余可购次数是否充足，购买成功后扣减资格次数。
•  用户详情页必须展示「优先购资格台账」（有效/过期/已用完）。
4.7 奖励类型统一（核心闭环）
•  全平台所有活动奖励下拉统一可选：藏品 / 优先购白名单资格 / 资格购资格 / 抽奖次数 / 盲盒。
•  每种奖励类型弹出对应配置面板：
•  藏品：选择已创建藏品 + 数量（计划上限，实际发放时动态校验配额预留库存）。
•  优先购资格：选择优先购活动 + 资格数量。
•  资格购资格：选择目标藏品（即用户获得该藏品的购买资格）+ 资格数量 + 有效期（精确到时分秒）。
•  抽奖次数：输入次数。
•  盲盒：选择已创建盲盒 + 数量（计划上限，实际发放时动态校验盲盒库存池）。
•  所有批量发放（空投、签到奖励、邀请奖励、抽奖奖品、盲盒奖励）生成完整发放记录台账，支持按活动/用户/时间筛选导出。
4.7.1 抽奖奖项概率闭环
•  抽奖活动奖项池支持添加多个奖项，每个奖项独立配置：奖项名称、奖品类型、奖品内容、中奖概率、奖项数量、奖项状态。
•  中奖概率：输入 0.0001 ~ 100 之间的数字，支持小数点后 4 位。
•  概率校验：所有「非空奖」奖项的概率之和必须 <= 100%；保存时系统自动校验，超出则拦截提示「中奖概率总和不得超过 100%，当前合计 X%」。空奖（未中奖）的概率 = 100% - 非空奖概率总和。
•  实际抽奖时采用预生成随机数 + 奖品库存实时校验双保险：先按概率命中奖项，再校验该奖项剩余库存/配额是否充足。若库存不足（如奖品藏品已发完），自动降级为空奖并记录异常日志，禁止超发。
•  奖项数量（计划上限）与实际发放脱钩，实际发放时动态校验对应奖品的配额预留库存或资格购资格余量。
4.7.2 盲盒子藏品概率闭环
•  每个盲盒关联 2~N 个子藏品（奖品），每个子藏品独立配置：
•  子藏品：从已创建的藏品中选择（流通量 > 0 或库存池 > 0 的藏品）。
•  中奖概率：输入 0.0001 ~ 100，支持小数点后 4 位。
•  计划数量：该子藏品在盲盒中的计划发放上限。
•  概率校验：所有子藏品的概率之和建议等于 100%；若小于 100%，差额部分视为「空奖」（未中奖）；若大于 100%，保存时拦截提示「子藏品概率总和不得超过 100%，当前合计 X%」。
•  子藏品库存冻结：配置盲盒奖品池时，系统不预先冻结子藏品库存；用户实际开启盲盒时，按概率命中子藏品，再实时校验该子藏品库存池/配额预留是否充足。若库存不足，自动降级为「空奖」并记录异常日志，禁止超发。
•  盲盒开启记录：记录每次开启的盲盒ID、用户、命中子藏品、发放状态、时间。
4.8 实名信息安全（核心闭环）
•  列表页：手机号中间4位脱敏（1388888）、姓名脱敏（张）、身份证号脱敏（110*********）。
•  查看完整实名信息（含身份证号全量）必须二次密码验证。
•  每一次完整查看行为写入审计日志（谁、何时、查看了谁的实名信息）。
•  实名认证管理模块只读，不提供修改/删除。
4.9 平台数据清除（最高风险闭环）
•  四重安全确认：
5.  弹窗红色警示，手动输入「确认清除」；
6.  输入管理员登录密码；
7.  输入短信验证码（发送至超管绑定手机）；
8.  点击「最终确认执行」。
•  清除范围：所有用户账号、钱包、藏品持有、盲盒持有、订单、转赠、签到/抽奖/邀请/空投/合成/盲盒记录、支付流水、钱包流水、邀请关系。
•  保留内容：管理员账号、藏品元数据（库存重置为发行总量）、盲盒元数据（盲盒库存重置为盲盒发行总量）、CMS内容、系统配置。
•  执行前自动备份全库，操作人/IP/时间/原因完整记录审计日志。
4.10 审计日志全覆盖
•  所有后台修改、批量导入、发放空投、配置活动、白名单操作、实名查看、强制回收、撤销转赠、平台清库、盲盒配置修改全部写入审计日志。
•  审计日志支持按操作人/模块/时间范围筛选，支持导出 Excel。

八、模块详细功能清单
8.1 数据仪表盘 /dashboard

•  基础信息
•  钱包资产（余额、交易记录）

•  邀请关系链：查看邀请码绑定关系、邀请统计、奖励发放记录。
8.3 实名认证管理 /realname（独立一级菜单，只读）
•  列表：用户ID、姓名（脱敏）、身份证号（脱敏）、手机号（脱敏）、认证状态、提交时间、审核时间。
•  搜索：姓名、手机号、认证状态、时间范围。
•  查看完整信息：需二次密码验证，展示完整姓名、身份证号、身份证正反面照片。
•  审计：每次完整查看写入审计日志。
•  权限：仅超管/风控/客服主管可见。
8.4 藏品管理 /collectible
•  创建藏品：名称、分类、发行总量、发行方、创作者、藏品故事、图片、描述、版税比例。
•  发售配置：时间、价格、每人限购、资格购开关、转赠开关、寄售开关。
•  可选配额配置：优先购/活动空投/其他配额，全部可选，任何时间可配置。
•  配置页顶部显示「发行总量 / 已售出发售 / 已配置配额 / 库存池 / 流通量」。
•  藏品列表：展示发行量、流通量、库存池、发售剩余、发售状态、资格购状态、寄售开关状态、转赠开关状态。
•  操作：
•  编辑（仅草稿状态）
•  发售配置
•  配额配置
•  重新上架（<= 库存池，二次确认+密码）
•  强制售罄（不清零，发售停止，剩余回库存池，二次确认+密码）
•  销毁（<= 库存池，二次确认+密码）
•  删除（仅草稿无关联，二次确认+密码）
•  强制回收（边界校验：校验二次流转，二次确认+密码）
•  独立空投（选藏品+数量+手机号批量换行，<= 库存池，二次确认+密码）
•  库存审计：一键校验「库存 + 用户持有 + 寄售中 + 转赠中 = 发行总量」是否守恒，展示差异。
8.5 盲盒管理 /blindbox（独立一级菜单）
•  创建盲盒：
•  基础信息：盲盒名称、盲盒图（上传）、描述、盲盒发行总量（份数，不可变更）。
•  状态：创建后为「已创建（草稿）」。
•  配置子藏品（奖品池）：
•  至少配置 2 个子藏品（最低要求，少于2个无法保存）。
•  每个子藏品配置：
•  子藏品选择：从已创建的藏品中选择（展示库存池 > 0 的藏品供选择）。
•  中奖概率：输入 0.0001 ~ 100，支持小数点后 4 位。
•  计划数量：该子藏品在盲盒中的计划发放上限。
•  概率校验：所有子藏品概率之和 <= 100%；若小于 100%，差额为空奖；若大于 100%，拦截提示「子藏品概率总和不得超过 100%，当前合计 X%」。
•  配置页顶部显示「盲盒发行总量 / 盲盒已售出发售 / 盲盒库存池 / 盲盒流通量」。
•  发售配置：
•  配置盲盒发售时间、发售价格、每人限购、发售数量（<= 盲盒库存池）。
•  配置后状态变为「发售中」。
•  盲盒列表：展示盲盒名称、盲盒图、盲盒发行量、盲盒流通量、盲盒库存池、发售状态、子藏品数量、发售价格。
•  操作：
•  编辑（仅草稿/已下架状态，可修改基础信息和子藏品概率）
•  发售配置（草稿->发售中）
•  重新上架（已售罄/已下架 -> 发售中，<= 盲盒库存池，二次确认+密码）
•  强制售罄（不清零，发售停止，剩余回盲盒库存池，二次确认+密码）
•  销毁（<= 盲盒库存池，二次确认+密码）
•  删除（仅草稿无关联，二次确认+密码）
•  强制回收（边界校验：校验是否已开启，已开启则拦截，二次确认+密码）
•  独立空投（选盲盒+数量+手机号批量换行，<= 盲盒库存池，二次确认+密码）
•  盲盒开启记录：查看所有用户开启记录（用户、盲盒、命中子藏品/空奖、开启时间、发放状态）。
•  盲盒库存审计：一键校验「盲盒库存池 + 用户持有盲盒 + 已开启盲盒 = 盲盒发行总量」是否守恒。
8.6 订单管理 /order

8.7 市场寄售管理 /market
•  藏品二级市场开关与价格管控：
•  针对单个藏品开启/关闭二级市场（Switch）。
•  价格管控模式：限价模式（固定金额，输入上限/下限）/ 不限价模式。
•  关闭后自动下架所有对应挂单。
•  审计日志记录。
•  寄售订单审核：待审核寄售申请（价格合理性、藏品合法性），支持通过/驳回/强制下架。若藏品全局二级市场关闭，待审核单自动标记「不可寄售」。
•  市场监控：查看在售挂单、成交记录、价格波动趋势图（ECharts）。
•  异常价格预警：针对限价藏品，超出阈值标红告警。
•  交易手续费配置：调整寄售手续费比例、最低/最高手续费限额（实时生效）。
8.8 转赠管理 /transfer
•  单品转赠开关：每个藏品/盲盒独立开启/关闭转赠（与寄售开关完全隔离）。
•  转赠记录查询：发起方、接收方、藏品/盲盒、状态、时间。
•  撤销转赠：边界校验（校验接收方当前持有状态，已流转则拦截），二次确认+密码。
•  转赠干预：强制取消待确认转赠、冻结涉及争议的转赠藏品/盲盒。
•  异常监控：标记高频转赠（刷单/洗钱嫌疑）、同一藏品/盲盒反复转赠，支持人工介入。
•  转赠统计：按日/周/月统计转赠量、涉及藏品/盲盒数。
8.9 营销活动 /marketing
•  优先购白名单管理：
•  活动创建、白名单 CRUD（用户ID、最大购买量、已用配额、有效期精确到时分秒）。
•  批量导入/导出。
•  过期资格清理（二次确认）。
•  签到活动：1-7天阶梯奖励、人群选择、一键空投。
•  奖励类型：藏品/优先购资格/资格购资格/抽奖次数/盲盒。
•  邀请活动：阶梯奖励（1-3-6-9）、注册奖励、邀请人奖励。
•  奖励类型：藏品/优先购资格/资格购资格/抽奖次数/盲盒。
•  抽奖活动：
•  奖项池管理：支持添加多个奖项，每个奖项独立配置：
•  奖项名称（如：特等奖、一等奖、空奖）
•  奖品类型：下拉选择（藏品 / 优先购白名单资格 / 资格购资格 / 抽奖次数 / 盲盒 / 空奖）
•  奖品内容：根据类型弹出对应配置面板
•  中奖概率：输入 0.0001 ~ 100，支持小数点后 4 位
•  奖项数量：计划发放上限
•  奖项状态：启用/停用
•  概率校验：所有「非空奖」概率之和必须 <= 100%，超出拦截提示。
•  抽奖资格配置：免费次数 / 消耗藏品兑换次数。
•  抽奖记录：用户每次抽奖结果、奖品发放状态、时间。
•  奖品发放：中奖后实时发放或生成待领取订单，发放失败进入补偿队列。
•  盲盒活动管理：
•  盲盒列表、状态管理、发售数据监控。
•  盲盒开启数据统计（总开启数、空奖率、各子藏品命中分布）。
•  合成活动：创建规则（目标藏品、所需材料、per_user_limit、total_limit、活动时间）、合成记录。
•  活动空投：批量手机号导入（换行分隔）、发放日志。
•  注册福利：新用户奖励配置。奖励类型：藏品/优先购资格/资格购资格/抽奖次数/盲盒。
•  活动数据：每个活动下方展示参与人数、转化率、库存消耗、用户反馈。
8.10 钱包与财务管理 /wallet
•  充值记录查询：所有充值流水（用户、渠道、金额、流水号、状态、回调时间），支持筛选导出。
•  资金流水审计：查看所有 wallet_transaction，按用户/时间/类型筛选。
•  手续费统计：按日/周/月统计平台手续费收入、分渠道收入（ECharts 图表）。
•  资金守恒校验：一键校验「所有用户余额总和 + 平台手续费 = 总充值 + 总奖励」，展示差异。
•  异常资金监控：标记大额充值、频繁小额充值（洗钱风险）、余额突变，生成告警列表。
8.11 CMS 内容管理 /cms
•  Banner 管理：配置首页轮播图（图片、跳转链接、展示时间、优先级），支持排序和上下线。
•  公告/资讯：发布公告/活动通知，支持定时发布、置顶、富文本编辑（编辑删除）。
•  帮助中心：编辑常见问题、用户协议、隐私政策、风险提示（版本管理）。
•  藏品文案审核：审核用户/运营上传的藏品描述、图片（涉黄涉政、版权风险），通过/驳回。
•  网页装修：修改登录/认证/下单/支付等按钮颜色、网站背景渐变色、金刚区名称和图片、网站全局名字、网站全局头像。
8.12 系统配置 /system
•  支付配置：支付宝/微信商户号、回调地址、验签密钥、沙箱/生产切换。
•  安全策略：交易密码错误次数阈值、锁定时间、限流规则（QPS/IP/用户）。
•  CORS/域名配置：允许的前端域名、API 访问白名单。
•  短信/OSS 配置：短信模板、OSS 存储桶、文件大小限制、格式白名单。
•  全局参数：平台名称、客服联系方式、最低充值金额、订单超时时间。
8.13 权限与审计 /permission
•  管理员账号：创建/编辑/禁用后台账号，分配角色。
•  角色与权限：定义角色（超级管理员、运营、客服、财务、风控），分配菜单和数据权限（按钮级）。
•  操作日志：记录所有管理员操作（谁、何时、改了什么、前后值），支持搜索导出。
•  登录安全：后台登录 IP 白名单、双因素认证（2FA）、登录失败锁定（可配置）。
8.14 风控安全 /security
•  交易密码锁定记录：查看用户锁定记录，支持手动解锁。
•  限流/封禁日志：被限流/封禁的 IP/用户、触发原因、解封操作。
•  异常行为监控：高频 API 调用、异常时间操作、异地登录、批量注册，风险等级标记。
•  安全事件审计：IDOR/越权尝试、支付回调篡改拦截、Token 异常使用。
•  敏感操作审批：大额退款、强制修改用户资产、修改支付配置等需二次审批（发起→审批人审核）。
8.15 客服工单 /ticket
•  工单列表：支付异常、藏品丢失、盲盒问题、转赠纠纷、账号问题，状态（待处理/处理中/已解决）。
•  工单处理：分配、回复用户、关联订单/藏品/盲盒、标记解决。
•  用户反馈查看：前端收集的反馈、举报、建议。
•  快捷操作：从工单直接跳转用户资产、订单详情、强制补偿/退款。
8.16 数据报表 /report
•  销售报表：按藏品/盲盒/日/周/月统计销售额、订单量、退款率（图表+导出）。
•  用户报表：新增用户趋势、留存率、实名转化率、DAU/MAU。
•  藏品报表：持有分布、流转次数、寄售率、热门排行。
•  盲盒报表：盲盒销量、开启率、子藏品命中分布、空奖率。
•  财务对账表：导出与支付网关对账文件（CSV/Excel）、手续费明细、资金流水。
•  自定义导出：按条件筛选导出任意业务数据（如订单、用户、藏品、盲盒），可选择字段后导出。
8.17 平台数据管理 /platform
•  一键清空用户数据：四重安全确认（输入「确认清除」+ 管理员密码 + 短信验证码 + 最终确认）。
•  清除范围：所有用户账号、钱包、藏品持有、盲盒持有、订单、转赠、签到/抽奖/邀请/空投/合成/盲盒记录、支付流水、钱包流水、邀请关系。
•  保留内容：管理员账号、藏品元数据（库存重置为发行总量）、盲盒元数据（盲盒库存重置为盲盒发行总量）、CMS内容、系统配置。
•  自动备份：执行前自动备份全库。
•  审计日志：操作人/IP/时间/原因完整记录。
