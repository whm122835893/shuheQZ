i一、通用说明

基础信息

Base URLhttps://api.shuhe-wenchuang.com/api/v1
认证方式JWT Bearer Token，Header: Authorization: Bearer {token}
Content-Typeapplication/json
分页参数page(页码,默认1) + page_size(每页条数,默认20)
时间格式ISO 8601: 2026-08-06T14:30:00+08:00（不含毫秒）
金额单位元（DECIMAL(10,2)，精确到分）
Token 与认证策略：
1. JWT 有效期 7 天，支持通过 refresh_token 续期（见 POST /user/refresh-token）
2. 修改登录密码或交易密码后，该用户所有 JWT 即时失效（加入 Redis 黑名单）
3. POST /user/logout 主动登出会将当前 Token 加入 Redis 黑名单即时失效
4. 所有以 is_ / has_ 为前缀的字段均为布尔类型（true/false），不使用 0/1

认证等级说明

标签含义说明
无需认证公开接口无需任何 Token
JWT需登录Header 携带有效 JWT Token
JWT + 交易密码需登录+交易密码JWT + Body 中携带 transaction_password（ bcrypt 校验）；仅 4 个端点：POST /market/listings、POST /collectibles/{id}/buy、POST /market/listings/{id}/buy、POST /transfers

HTTP 状态码映射

HTTP Status含义使用场景
200OK请求处理成功
400Bad Request参数错误/格式不合法/文件异常隔离
401Unauthorized未认证 / JWT 缺失或已失效
403Forbidden无权限 / 操作他人资源 / 账号被禁用
404Not Found资源不存在
409Conflict业务冲突（重复操作/库存不足）

业务码（响应体 code）与 HTTP 状态码保持一致取值，便于网关与前端统一处理。

设计说明：
1. 所有需交易密码的接口（仅 4 个：POST /market/listings、POST /collectibles/{id}/buy、POST /market/listings/{id}/buy、POST /transfers）均为涉及资产变动的敏感操作，交易密码在 Body 中传输，后端 bcrypt 校验，且为业务逻辑第一步
2. 盲盒开启、抽奖、合成仅 JWT 认证，绝对不涉及交易密码
3. JWT 有效期 7 天，支持 refresh_token 续期；修改登录密码或交易密码后该用户所有 Token 即时失效（Redis 黑名单）
4. 支付回调、充值回调为第三方服务器调用，不走 JWT 认证，通过签名验签保障安全；幂等键为 transaction_no，重复回调直接返回 "SUCCESS"
5. 订单 expires_at 为 15 分钟，定时任务每 5 分钟扫描超时未支付订单自动取消并释放库存；优先购下单复用发售购买逻辑，区别仅在于额外校验白名单资格和时间窗口
6. 库存共用：优先购与公售共用 nft_collectibles.circulate / locked_quantity，未单独拆分；所有乐观锁均基于对应表 version 字段（user_collectibles.version / collectibles.version / wallets.version 等）
7. 抽奖次数可配置化：来源含 register/invite/checkin/hold_collectible 等；获得新藏品后（支付回调、转赠确认）异步检测 hold_collectible 规则发放次数
8. 转赠/盲盒/抽奖/签到的奖励结果由前端弹窗即时展示，不写入消息中心
9. 所有涉及藏品归属变更的操作（购买/转赠/合成/盲盒/抽奖）均写入 nft_operation_logs 审计；链上标识（contract_address / tx_hash / token_id）在 API 返回时一律脱敏展示
10. 所有 is_/has_ 前缀字段均为布尔类型（true/false）；时间戳统一不含毫秒
